# ADR-015 Settings, pause and data controls — Accepted (M8)
**Where settings live.** One validated object `settings` inside the existing `br:state` key (`paused`, `retentionMonths` (3/6/12/24/null), `capMb`, `mirrorDeletion`); older stored state parses to the defaults (not paused, 12 months, 1000 MB, mirroring on). Changes go through `sw/settings-set` (strict zod patch, trusted extension pages only).
**Pause** stops live history sync, the initial import (clean checkpoint stop), the reconcile alarm and Deep Search capture; maintenance (retention/cap cleanup) keeps running. `lastReconcileAt` is not advanced while paused, so resuming runs a reconcile that covers the whole paused period. A restart while paused stays paused. The toolbar badge `II` shows the paused state.
**Mirrored deletion off**: `onVisitRemoved` is ignored entirely (including "clear all"); Saved items are never removed by mirroring in either mode (ADR-006 unchanged).
**Retention/cap** are read by the daily maintenance run (`applyRetention(months|null)`, `enforceCap(capMb·10⁶)`); changes apply at the next run, not retroactively at save time.
**Data controls** call the existing engine deletions (page, site with optional `includeSaved`, date range, all-except-saved, everything). Destructive actions use an inline two-step confirm; the two wholesale deletes also require typing `DELETE`. Deep Search text can be cleared separately without touching History or Saved (`clearDeepContent`, ADR-014).
**Ledger** adds two read-only engine calls (`domainStats`, `pageInfo`); `pageInfo` returns at most a 600-character preview of stored text.
**Export/import** is local-file JSON validated by the strict `exportDataSchema` (version 1, ≤ 50 MB, data only, never evaluated) and applied through the existing `importData`.
