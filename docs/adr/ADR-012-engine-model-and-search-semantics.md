# ADR-012 Engine domain model, protocol and search semantics — Accepted (M2)
**Model** (schema v1, `src/engine/schema.ts`): `pages` (one row per normalised URL; `flags` = history 1 | content 2 | saved 4; first_seen, last_visit, visit_count, typed_count, lang, saved_at, content_hash, content_indexed_at), `contents` (original headings/description/body + UTF-8 byte count, exactly once), `snippets` (user quotes keyed by URL, survive page deletion), FTS: `fts_main` (contentless, folded title/headings/description/body), `fts_meta` (trigram over folded title + URL), `fts_snip`, `fts_vocab` (fts5vocab, for "did you mean"). Source tier shown to the UI: saved > snippet > deep > history. No speculative fields (no tags, no vectors, no per-visit table: the blueprint's optional `recent_visits` stays out until a milestone proves last-visit filtering inadequate).
**URL identity**: http(s) only (A6), fragment and credentials removed, tracking parameters (`utm_*`, `fbclid`, `gclid`, …) removed, ≤ 2048 chars. Token-like query parameters are a capture-policy concern (M6).
**Protocol**: UI → service worker `{type:'sw/engine', call}` → offscreen `{target:'engine', type:'engine/call', call}` → worker `{id, call}`. `call` = zod discriminated union on `method` (`src/engine/contract.ts`), validated at the SW gate and again in the worker; results typed by `EngineResults`; errors carry a code (`engine-unavailable | open-failed | db-too-new | bad-request | internal`). All calls are retry-safe (reads; upserts/idempotent deletes in one transaction); only `engine-unavailable` and "channel closed / receiving end missing" are retried (8 attempts, 50 ms → 1 s). Calls are executed one at a time by the worker (single owner, no interleaved multi-statement operations). Raw SQL never crosses the boundary; UI code never imports SQLite.
**Search**: parse (total, folded alphanumeric tokens only) → closed FTS grammar (quoted token groups, `*`, `OR`; bound as a parameter) → bm25 top-200 → TypeScript re-rank (bm25 relative to best, title/URL hit, recency τ=45 d, log visits, saved bonus, phrase adjacency) → snippets/highlights from the original text. Last bare word matches as a prefix. Fewer than 5 exact results → relaxation: any-term (≥3-char tokens, ≤40 candidates), then trigram substring on title/URL; relaxed results are flagged `approximate` and always listed after exact ones; "did you mean" only for unknown words (a prefix of an indexed word is not a typo). Exclusions use `NOT IN (SELECT rowid … MATCH ?)`. Filter-only queries list by recency; exclusions alone and empty/punctuation-only queries return nothing. `is:saved` → saved pages; `is:snippet` → snippets; neither → both. Dates: `after:` inclusive, `before:` exclusive, local day boundaries via `tzOffsetMinutes`; relative `d/w/m/y` = 1/7/30/365 days.
**Deletion**: `deleteUrls/Domain/Range/AllExceptSaved` remove non-saved pages (contents, both FTS rows) and only clear the history flag of saved pages; `deleteDomain(includeSaved)` and `deleteEverything` also remove saved pages and snippets. Retention = `deleteRange(0, now − months·30 d)`; storage cap trims Deep text first, then oldest non-saved pages (bounded loops). ADR-006's expiry guard is NOT in the engine: it needs the stored last-visit per URL and is applied by the M3 history layer (the engine will expose a `lastVisits` read for it).
**Maintenance/health**: `maintenance` = bounded `incremental_vacuum` (only when the free list ≥ 64 pages; ≤ 500 pages per call) + optional bounded FTS merge; designed for a daily alarm, never per write. `integrityCheck` (SQLite + FTS5 integrity-check + page/FTS row-count consistency) costs ≈ 5 s at 20K pages: scheduled/diagnostic use only.
**Revisit when**: the real relevance set (M10) disagrees with the weights; p95 on prefix-heavy queries exceeds budget at real-world sizes (levers: minimum prefix length, smaller candidate sets, lazy snippets).
