# ADR-014 Deep Search capture — Accepted
**Decision.** Deep Search is opt-in and gated four times before any page is read: user enabled it (`br:state.deep.enabled`), history consent is valid, the optional host permission is actually held for the page's origin (`permissions.contains`), and the page is eligible. Capture is driven by the service worker (ADR-004): `tabs.onUpdated` (status `complete`) → `scripting.executeScript(extractPage, deep: true)` → engine `upsertContent` with a SHA-256 content hash. No `content_scripts`, no required host permissions.
**Permission lifecycle.** `permissions.request` runs only in an extension page on a click (`settings.html`); the service worker re-verifies with `permissions.contains` before setting `enabled`, and `permissions.onRemoved` and every service-worker wake reconcile `enabled` to the real permission. Turning Deep Search off or losing the permission deletes nothing; deleting Deep text is a separate explicit action (`clearDeepContent`, optionally per domain).
**Eligibility.** Public http(s) pages only: no URL credentials, no IP literals, no single-label/`.local`/`.internal`/`localhost` hosts, no incognito, no user-excluded site (subdomains included), no non-HTML, no password or payment-card fields, at least 200 characters of text. Caps: 50 KB body / 5 KB headings / 1 KB description (extractor and engine).
**Duplicates/updates.** Same URL = one page row; identical content hash = no write; changed text replaces the stored text. A page also in history keeps its history data; Chrome history deletion still removes Deep-only text (ADR-006/012).
**Not decided here.** Dwell-time or visit-count thresholds, per-page "never index", a settings home beyond Deep Search (M8), SPA route-change capture.
**Test-only seam.** The e2e build holds a required host permission for `fixture.test`; the worker then checks that permission instead of the optional patterns (`getManifest().host_permissions ?? optional patterns`). The production manifest has no `host_permissions` (asserted).
