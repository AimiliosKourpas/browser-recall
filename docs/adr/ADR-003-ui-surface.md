# ADR-003 UI surface — Accepted: iframe overlay with popup-window fallback (with required mitigations)
Evidence: docs/spikes/M0-RESULTS.md S6 (fixtures only; the real-site matrix is for M7).
Works: plain, strict page CSP, `frame-src 'none'` page CSP (extension frames are exempt), framed pages, fullscreen (host uses `popover="manual"` → top layer). Focused ~40 ms after the command; keystrokes invisible to page scripts. `chrome://` and `about:blank` fall back to a popup window.
Required: (1) the search page must move focus to its input on window `focus` (iframe.focus() alone leaves nothing focused); (2) the host must set `document.body.inert = true` while open — a page that refocuses its own input every 50 ms otherwise swallows typing AND receives every keystroke (24 events leaked in the test); restore on close; (3) closed shadow root + single iframe; (4) `use_dynamic_url: true` works and blocks `fetch` probing of the static extension URL.
Decision gate for M7 unchanged: if the 15-site matrix is poor, ship popup-only.

M1 note: the manifest declares NO `web_accessible_resources` yet (tests enforce this). M7 adds the search page as a WAR with `use_dynamic_url: true` through this ADR; in M1 the search page opens only as a popup window (toolbar click / shortcut).

## M7 implementation record
Implemented as specified: `src/overlay/host.ts` (host `div[popover=manual]` with a closed shadow root: click-away backdrop + one iframe of `search.html?overlay=1`), injected on demand by the service worker with `scripting.executeScript({files:['overlay-host.js']})` under activeTab (toolbar click / command) — not a content script, still no `content_scripts` and no `host_permissions` in production. `body` gets the `inert` attribute while open and its original attribute (absence, or value) is restored exactly on every close path, failure and `pagehide`. Page CSS cannot hide the host: all geometry/visibility are inline `!important`; a zero-size result is treated as failure. Search page hands focus to the input on window focus. Close from inside the frame goes through `sw/overlay-close` (service worker relays to the sender's tab) — no `postMessage`. The injected host answers only the service worker (`sender.id` own, no `sender.tab`).
Manifest: `web_accessible_resources: [{resources:['search.html'], matches:['https://*/*','http://*/*'], use_dynamic_url:true}]` (tests pin it). Invocation toggles (second invocation closes). Any failure (restricted URL, injection error, host silent/not rendered) opens the popup window; search never becomes unavailable.
Not done in the cloud: the 15 real-site matrix (`docs/qa/overlay-matrix.md`, owner manual test); the decision gate to ship popup-only stays available.

## Release fix (real Chrome 153 QA)
`search.html` was both the popup/tab page and the web-accessible overlay page (`use_dynamic_url: true`). `chrome.runtime.getURL()` returns the dynamic GUID URL for such a resource, and **Chrome 153 blocks extension-initiated top-level navigations to dynamic-URL resources** (`windows.create`/`tabs.create` → ERR_BLOCKED_BY_CLIENT "blocked by Chrome"); Chrome 116 and 141 allow it (reproduced with Chrome for Testing 153.0.8010.50 / 141 / 116). Decision: the overlay iframe loads a dedicated `overlay.html` (same app, second HTML entry), which is the ONLY web-accessible resource; `search.html` is an ordinary, non-web-accessible extension page opened top-level. Iframe loading of the dynamic URL still works on 153 (e2e). Chrome 116–129 ignore `use_dynamic_url`, so on those versions a web page can frame `overlay.html` by its static URL (it is a cross-origin frame with no access to extension data); `search.html` is never frameable.
Also: sqlite-wasm's automatic `opfs`/`opfs-wl` VFS installation is disabled via `sqlite3ApiConfig` (we use only `opfs-sahpool`); it produced console errors listed on chrome://extensions.
