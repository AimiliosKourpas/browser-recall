# ADR-007 Encryption at rest — Accepted: not encrypted; documented threat model, no encryption claim
Context: the index (history titles/URLs, optional page text, saved items) is stored in the extension's private browser file system (OPFS) and `chrome.storage.local`.
Decision: V1 does **not** encrypt the index and makes **no claim** of encryption. Any key held by the extension would sit in the same profile as the data (or require a passphrase prompt that breaks the instant, keyboard-first search and the service-worker restart model), so it would not stop an attacker with profile or OS-account access, which is the only realistic local threat. Protection relies on the operating system account/disk encryption and Chrome's profile isolation.
Consequences: onboarding, Settings → About and the privacy policy state plainly that the index is not encrypted and who can read it (`docs/THREAT-MODEL.md`). Exports are plain JSON. Revisit post-V1 only with a design that does not weaken search latency or resilience (user passphrase option).
