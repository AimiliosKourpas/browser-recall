# ADR-013 History pipeline: consent, resumable import, live sync, schedules — Accepted (M3)
**Consent**: versioned (`CONSENT_VERSION`), stored in the pipeline state; granted only by a trusted extension page through `sw/grant-consent` (the onboarding button "Allow and import history"). Without valid consent the pipeline never queries `chrome.history`, never calls the engine and creates no alarms (unit + e2e tested, including after a browser restart). Install/update opens the consent page only when consent is missing or outdated. Declining = inert. **Revocation** (`sw/revoke-consent`) stops processing, clears the checkpoint and alarms and leaves indexed data untouched; deleting data is an explicit M8 control (the spec defines no automatic erase-on-revoke).
**State**: ONE `chrome.storage.local` key (`br:state`, zod-validated; corrupt/missing = defaults = no consent). Serialised read-modify-write. No other store.
**Import**: runs in the service worker (the onboarding page is only a view, polling `sw/pipeline-status`). Earliest visit found by binary search (~42 cheap queries), then 7-day windows newest → oldest, `maxResults` 50,000 (a full window is split), engine writes ≤ 1,000 rows per call, non-http(s) skipped. Checkpoint (`nextEnd`) persisted after every window; idempotent upserts make re-runs safe. The SW re-enters the import on every wake (`onWake`), and a 1-minute `br-import-watchdog` alarm exists only while an import is unfinished.
**Live sync**: `history.onVisited` → single-row idempotent upsert (an empty title never erases a known one); engine failure sets `reconcileDue`; `br-reconcile` (daily) and startup re-read the last day+ of history. `history.onVisitRemoved` → ADR-006.
**Schedules**: named alarms re-created idempotently on install, startup, wake, consent and after every alarm (Chrome does not reliably keep alarms across restarts): `br-reconcile` and `br-maintenance` daily; maintenance = `applyRetention(12 months)`, `enforceCap(1 GB)`, bounded `maintenance`, weekly `integrityCheck` (defaults from PRODUCT_SPEC §5.6 until the M8 settings UI).
**Not decided here**: pause/resume UI, per-site exclusions, ledger (M8); Deep Search capture (M6).
